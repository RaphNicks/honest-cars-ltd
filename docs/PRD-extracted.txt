1 Purpose, Scope & How to Use This Document
What this document is, who it is for, and how decisions get made
1.1 Purpose
This working document is the single source of truth for designing and building honestcarsltd.com,
the official digital platform of Honest Cars LTD. It translates the company’s Business Operating
Document (v1.0) into a concrete website: a minimalist, listings-first storefront fed by dealer-
partner inventory, wrapped by the complete suite of HonestCars services and products, and backed
by portals/tools that allow the team to run the day-to-day business through the website.
1.2 The One-Sentence Brief
BRIEF IN ONE LINE
Build a fast, mobile-first, minimalist website where the cars are the hero and every visitor is
never more than two clicks from any HonestCars service — while the back-office quietly powers
listings, leads, bookings, payments, dispatches and reporting for the operations team.

2.4 Guiding Product Principles
1. Cars front and centre
The store is the beachhead. Search, inventory
and car cards dominate the homepage; services
orbit them visibly.
2. Two clicks to anything
Every service and product is reachable in ≤ 2
clicks from anywhere (persistent nav + smart
cross-links).
3. Mobile is the product
Most visitors arrive on phones over mobile data.
Design mobile first; treat PC as an
enhancement, not the baseline.
4. Speed is a feature
Every image, script and font is justified against a
performance budget (§12, §13). Slow = broken.
5. Trust is visual, not claimed
Verification badges, inspection grades, price-
position indicators and real photos do the
persuading — not adjectives.
6. Protect the middleman position
Dealer contact details are never exposed; all
buyer contact flows through HonestCars
channels (enquiry forms, masked WhatsApp).
7. WhatsApp is a native citizen
Deep links, share previews and chat CTAs
everywhere — that is how this market transacts.
8. Minimalism with warmth
Whitespace, restraint, one accent action colour
— paired with plain-language, human copy (§3,
§16).

3 Brand & Design Direction — The Minimalist System
Look, feel, voice and the rules that keep it honest
3.1 Design Personality
“A quiet showroom run by a straight-talker.” Minimalist and functional like a premium
showroom — nothing decorative without a job — with the frankness of a trusted mechanic. Reference
feel: clean automotive marketplaces (white space, strong photography, disciplined grids) crossed with
a modern fintech’s clarity.
3.2 Colour System
Token Hex Usage
--honest-navy #0E2A47 Primary brand — headers, footer, headings, key text
--honest-green #12A150 The one action colour — primary CTAs, verified badges, success
states
--honest-amber #E8A13D Sparing accents — “Field-Checked” badge, warnings, highlights
(never for primary CTAs)
--ink / --muted #1D2733 /
#5B6B7C
Body text / secondary text
--surface / --
line
#F7FAFC /
#D8E0E8
Card backgrounds / dividers & borders
--white #FFFFFF Dominant canvas — the site should feel mostly white
3.3 Typography & Iconography
Primary typeface: Inter (self-hosted; system stack -apple-system, Segoe UI, Roboto  as instant
fallback). One family only, weights 400/500/600/700.
Scale (mobile base): 12 / 14 / 16 (body) / 20 / 24 / 32 — headings clamp up on desktop; never
below 14px for readable content.
Prices always in ₦ with figure-friendly tabular styling; mileage in km.
Icons: single-line icon set (e.g., Lucide/Feather style), 1.5px stroke, no mixing of icon families.
3.4 Layout & Component Rules
8px spacing grid; max content width 1200px; generous whitespace; no carousels that hide
content (static grids with “View all”).
Cards: white, 1px #D8E0E8 border, 12px radius, subtle shadow on hover (desktop only).
Buttons: 3 kinds only — primary (solid green), secondary (navy outline), ghost (text). One primary
action visible per screen area.
Photography direction: real lot photos, daylight, consistent framing guide issued to dealers
(front ¾, side, rear ¾, interior, dashboard, engine bay, odometer close-up). No stock-photo
handshakes.
Motion: ≤ 200ms ease transitions; no parallax, no autoplay sliders, respect prefers-reduced-
motion .

3.5 The Trust Component System (signature UI)
Component Meaning & Visual
Verification
badge
Three grades shown on every car card & VDP: ● Network-Listed (grey — dealer data,
unverified) · ● Field-Checked (amber — physically seen) · ● HonestCars-Certified (green
— full inspection passed). T ooltip explains each grade in one line.
Price-Position
indicator
Subtle label on VDP: “Within market band / Below market / Premium” — driven by the
pricing database (§10). Where price history exists, show “price unchanged 21 days”.
Documents
strip
Icon row: Customs verified ✓ · Registration ✓ · Duty papers sighted ✓ — green when
verified, grey when pending.
Timeline chip “Listed 3 days ago · Updated today” — freshness is trust.
Honest note A short, plainly-written condition truth on certified cars, e.g. “AC blows cold; two panels
resprayed; tyres at ~60%.” Framed box, amber border.
3.6 Tone of Voice
Plain English, short sentences, zero jargon without explanation, numbers over adjectives. Say “We
checked this car ourselves on 14 Sept” not “quality assured”. Humour allowed in content hub, never
in checkout flows. Write like the honest friend who knows cars — never like a marketer.

5.2 Navigation Model
Desktop header (sticky, white, slim): Logo · Buy Cars · Services ▾ (mega-menu with 8 services,
icon + one-liner each) · Sell/Swap · Hire · Blog · Search icon · Account icon · [Find My Car]
primary green button.
Mobile: hamburger opens full-height drawer (same items, accordion Services). Persistent
bottom bar (after first scroll): Home · Cars · Find My Car · Chat (WhatsApp) · Account.
Persistent floating WhatsApp button bottom-right on all public pages (respects bottom nav —

Footer: 4 columns — Shop (All cars, Compare, Find My Car, Sell/Swap, Hire) / Services (all 8 +
shop links) / Company (About, Verification, Partner, Blog, Contact, Careers-later) / Legal; plus
contact block, CAC/registration line, payment-partner marks, and “Port Harcourt, Nigeria” local
note.
Cross-links: every service page ends with related listings or related service cards; every VDP
surfaces inspection, concierge, tracking and hire cross-sells (§6.3). This is how the “plethora of
services” stays discoverable without cluttering the store.
THE 2-CLICK ACCEPTANCE TEST
From the homepage, a first-time mobile user must reach any of: (a) a car listing, (b) the
concierge form, (c) an inspection booking, (d) the shop, (e) WhatsApp chat — in no more than 2
taps. QA verifies this in §18.3.

Technical Approach & Stack
The website will be built using the following approved technology stack. This stack is the implementation baseline for the project.
17.1 Approved Technology Stack
Frontend: Vanilla HTML, CSS & JavaScript
Backend: Node.js
Database: MySQL
PHP: Only where specifically required for an existing integration or
isolated server-side utility.
17.2 Architecture Direction
Browser · Vanilla HTML/CSS/JavaScript · Node.js API / application server
· MySQL database
PHP is a server-side programming language, not a database. It must not
replace Node.js as the primary backend or MySQL as the database.
CI lint/test checks.
· Use environment variables/secrets management and daily database
backups.
· Provide documented handover covering the repository, hosting, DNS,
environment setup, and deployment.
· No frontend frameworks; use semantic HTML, modern CSS, and modular vanilla JavaScript.
